## 5. 已知限制与未解决事项

| # | 限制 | 性质与影响 |
|---|---|---|
| L-1 | `chengxiang` 注册项 `path = None` | 该条目无法作为本地只读目标；`read_project` 只会返回 `not_locally_accessible`，`read_file`/`search_project` 会在 `get_local_project_root` 处抛 `ValueError`。**不是错误状态，而是"未登记本地路径"**。 |
| L-2 | `read_project()` 在路径有效时会调用 `git status` 子进程 | argv 固定、无 `shell=True`、`timeout=10`；但 `git status` 在特定仓库下可能刷新 `.git/index` 的 stat 缓存，构成**理论上的**文件系统副作用。D-5.18 全程未调用 `read_project`，故该副作用未被实际触发或验证。 |
| L-3 | 只读工具测试不能证明修改工具的生产安全性 | D-5.18 只验证读路径；`modify_file` 的备份、原子替换、失败回滚等行为仅有单元测试覆盖，**未经真实项目验证**。 |
| L-4 | 同进程代码可伪造全局审批状态 | `PLAN_APPROVAL` / `AUTHORIZED_PERMISSION` / `STATE` 是模块级全局；同进程内的任意代码可直接改写以绕过审批。**这是已知架构限制，不是 D-5.18 的遗漏**，需通过进程隔离或独立 UID 才能缓解。 |
| L-5 | `tests/` 目录整体未被 Git 跟踪 | `git ls-files tests/` 为空；28 个 `.py` 文件全部为未跟踪状态。工作区一旦被重置或清理，测试资产将丢失。Git 无法对测试改动提供 diff/stash 保护。 |
| L-6 | 26 个既有测试文件未逐个保存本轮前的 SHA-256 | A1-P3 仅以 **mtime（均早于本轮运行）** 与"本轮只创建了一个文件"作为未改动证据，**不是逐文件哈希前后对比**。已在当时报告中如实披露。 |
| L-7 | `type="test"` 是测试项目新增的字段值 | 既有取值为 `orchestrator` / `qq_bot` / `web_app`。已核实 `main.py` 不读取 `type` 字段，但**生产 schema 未对该新值做任何校验或文档化**。 |
